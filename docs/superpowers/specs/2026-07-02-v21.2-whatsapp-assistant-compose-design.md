# v21.2.0 — WhatsApp Assistant "Compose" Redesign

**Date:** 2026-07-02
**Branch:** `v21.2.0` (forks from `v21.1.0`)
**Status:** design approved (Variant A), decisions locked

## Goal

Turn the WhatsApp Assistant from a raw **data dump** into a **compose-message**
surface. The single HR officer picks an employee with open attendance issues,
sees a **live WhatsApp preview** of the message that will land on the employee's
phone, tweaks tone / adds a note / edits inline, and sends via WhatsApp with the
text **already prefilled** — then optionally marks them "sudah dihubungi".

Scope is deliberately kept to **open issues** (missing punches / absences with no
reason yet) for the active month — the same population the screen serves today.
No lateness/recap expansion in this version.

## Why (problems with today's screen)

1. **WA Web opens EMPTY.** `_open_wa_web` calls `https://wa.me/<digits>` with no
   `?text=`. The officer must copy → switch → paste. wa.me supports prefilled
   text; we are not using it.
2. **The content is a fact list, not a message** — no greeting, context, ask, or
   HR sign-off. It always needs rewriting before sending.
3. **No "contacted" memory**; phone status only shows up *after* clicking.

## Approved design (Variant A)

Right panel becomes a vertical compose stack; the **signature** element is a
faithful **WhatsApp preview** (deep-green bubble `#005C4B` on a `#0B141A`
"wallpaper", `HARI INI` day pill, time + blue `✓✓`). The Kirim CTA borrows
WhatsApp green because the action *is* WhatsApp — a subject-motivated accent, not
decoration. Magenta stays the app's brand accent elsewhere.

### Locked behavior decisions

- **Mark "sudah dihubungi" = MANUAL only.** A dedicated button marks/unmarks.
  Clicking **Kirim via WhatsApp** does **not** change contact status (opening WA
  ≠ message actually sent).
- **Preview text is EDITABLE.** The green bubble is a live text box. Tone
  (Formal / Ramah) and an optional Catatan **(re)generate** the text into the
  box; the officer may then hand-edit freely. The box is the source of truth for
  both **Kirim** and **Salin**.

## Architecture (units + boundaries)

| Unit | File | Responsibility | Depends on |
|------|------|----------------|-----------|
| Message builder | `src/core/wa_message.py` (new) | Pure functions: build the Formal/Ramah message text from structured issues + HR officer name + note; phone → `wa.me?text=` URL. No I/O. | stdlib only |
| Contact log (DB) | `src/db/wa_contacts.py` (new) | `mark_contacted` / `unmark_contacted` / `is_contacted` / `contacted_map`. Per `(employee_id, year_month)`. | sqlite3 |
| Schema | `src/db/schema.py` | add `wa_contacts` table to DDL (new table → `CREATE TABLE IF NOT EXISTS` migrates existing DBs, no ALTER). | — |
| Screen | `src/ui/screens/whatsapp_assistant.py` (rewrite) | Compose UI: identity header, issue chips, tone segmented + note, editable WA preview bubble, actions, list with phone dot / search / contacted state. | the three above + theme |

Keeping the message logic and contact persistence as pure/isolated units means
both are unit-tested without Tk, and the screen stays a thin view.

### `wa_contacts` table

```sql
CREATE TABLE IF NOT EXISTS wa_contacts (
    employee_id  INTEGER NOT NULL REFERENCES employees(id) ON DELETE CASCADE,
    year_month   TEXT    NOT NULL,           -- 'YYYY-MM'
    contacted_at TEXT    NOT NULL,           -- ISO timestamp
    PRIMARY KEY (employee_id, year_month)
);
```

Mirrors `coaching_sessions`. Contact status is naturally scoped to the active
month, so a new month starts clean.

### Message builder contract

`build_wa_message(nama, year_month, issues, hr_officer_name, *, tone="formal",
note="", hour=None) -> str`

- `issues`: list of dicts `{"hari", "tanggal", "masuk", "keluar"}` (as fetched
  from `attendance_records`), ordered by date.
- Kind phrase from punch presence: both None → `tidak tercatat hadir`; masuk None
  → `belum ada absen masuk`; keluar None → `belum ada absen pulang`; else
  `absensi perlu dicek`.
- Line: `• {Hari3}, {d} {Bln3} — {kind}` (e.g. `• Sen, 5 Mei — belum ada absen masuk`).
- Greeting depends on `hour` (injectable; default = wall clock): <11 pagi,
  11–14 siang, 15–17 sore, else malam.
- `hr_officer_name` blank → sign `— HR`.

**Formal:**
```
Selamat {pagi}, Sdr. {Nama Title}.

Dari rekap absensi {Bulan} {Tahun}, ada {N} catatan yang belum terkonfirmasi:
{lines}
{note?}Mohon konfirmasi atau alasannya agar data dapat kami perbarui. Terima kasih.

— {HR Officer}, HR
```

**Ramah:**
```
Halo {NamaDepan} 👋

Ada {N} catatan absensi bulan {Bulan} yang belum terisi:
{lines}
{note?}Boleh dibantu konfirmasi ya biar bisa kami update 🙏 Makasih!

— {HR Officer} (HR)
```

`{note?}` = when a note is given, insert it as its own paragraph before the ask.

`normalize_phone_id(phone) -> str | None` — Indonesian normalization (leading `0`
→ `62`, digits only, valid 10–15 digits else None). `wa_me_url(phone, text) ->
str | None` — `https://wa.me/{digits}?text={urlencoded}` or None when phone
invalid. Reuses the exact rules currently in `_open_wa_web`.

## UI layout (right = compose)

1. **Identity header** — avatar (initials, deterministic color), name
   (`FONT_DISPLAY`-ish), `DEPT · +62…` (mono), phone-status pill
   (`✓ Nomor tersedia` / `⚠ Nomor belum diset`), issue-count caption.
2. **Issue chips** — one per open issue: colored square (amber = lupa absen, red
   = tidak masuk) + `Hari · d Bln` + kind. Wraps.
3. **"Susun pesan"** divider → **tone** `CTkSegmentedButton` (Formal | Ramah) +
   **＋ Catatan** toggle revealing a small text field.
4. **WA preview** — `#0B141A` frame with `HARI INI` pill and an **editable**
   green `CTkTextbox` bubble; time + `✓✓` footer. (tk has no wallpaper doodle /
   gradient / bubble tail → solid fills, honest to the ridge precedent.)
5. **Actions** — `🟢 Kirim via WhatsApp` (green; disabled + hint when no phone),
   `📋 Salin teks`, and a right-aligned `✓ Tandai sudah dihubungi` toggle.

**Left list** gains: a search box (filter by name), a **phone status dot** (green
= number set, gray = not), the count badge, and a **contacted state** (row dims,
shows `✓`, sinks below un-contacted names).

## Out of scope (YAGNI)

- Lateness / recap messages (kept to open issues).
- Bulk / multi-select send.
- Real WhatsApp API send (still officer-in-the-loop via `wa.me`).
- Editing an employee's phone number here (Settings/import own that).

## Testing

- `wa_message`: kind mapping, line format, Formal & Ramah scaffolds, note
  insertion, greeting-by-hour, blank-officer sign-off, phone normalization
  (08→62, +62, invalid length → None), `wa_me_url` prefilled + urlencoding.
- `wa_contacts`: mark → is_contacted True; unmark → False; `contacted_map`
  returns only the month's rows; upsert idempotent.
- `schema`: fresh `init_db` creates `wa_contacts`; migration on a pre-existing DB
  (without the table) adds it.
- Screen smoke: builds headless, selecting an employee renders the compose panel;
  no exceptions.
